# Novel Agent MVP 发布前检查清单

> 适用范围：当前仓库的 MVP 版本发布前人工检查。
>
> 说明：本项目目前更接近“小说生成能力集合 + 最小 CLI 入口”，不是生产级、全自动小说流水线。以下清单用于判断“是否适合对外演示或小范围试用”，不是证明项目已经生产可用。

## 1. 发布定位与范围确认

- [ ] 明确本次发布定位为 MVP / 内测 / 演示版，而不是“生产可用”版本。
- [ ] README、发布说明、对外沟通中没有夸大为“一键完成整本小说生成”。
- [ ] 明确当前 CLI 实际主流程是否与 README 描述一致。
- [ ] 明确哪些能力只是“已有模块”，哪些能力已经“接入当前主流程”。
- [ ] 确认失败重试、日志、观测性、长期运行稳定性仍不作为本次发布承诺。

## 2. 环境变量与密钥检查

- [ ] 检查 `.env.example` 是否覆盖当前运行所需最小环境变量。
- [ ] 手动确认 `.env.example` 中的变量名与 `config.py` 实际读取一致：`OPENAI_API_KEY`、`OPENAI_BASE_URL`、`MODEL_NAME`。
- [ ] 确认 README 中环境变量说明与 `.env.example` 一致。
- [ ] 确认本地 `.env` 未被误提交。
- [ ] 确认测试数据、示例文档、README 中没有泄漏真实密钥。
- [ ] 若使用 OpenAI 兼容接口，手动确认 `OPENAI_BASE_URL` 指向可用端点，且模型名与供应商实际配置匹配。
- [ ] 手动验证缺失环境变量时，报错信息是否足够清晰，能直接指出缺少哪个变量。

## 3. README 完整性检查

- [ ] README 明确写出项目目标、当前边界、不是完整生产系统这一事实。
- [ ] README 提供 Python 版本要求。
- [ ] README 提供虚拟环境创建与依赖安装步骤。
- [ ] README 提供 `.env` 配置步骤。
- [ ] README 提供最小运行方式，例如 `python app.py`。
- [ ] README 提供最小测试运行方式，例如 `pytest -q` 或最小相关测试命令。
- [ ] README 明确说明 `prompts/`、`data/`、`tests/` 的用途。
- [ ] README 对“已存在模块”和“已接入主流程”的区分没有含混表述。
- [ ] README 中的命令、路径、文件名与仓库当前实际结构一致。
- [ ] README 编码显示正常，没有中文乱码、异常字符或不可读段落。

## 4. 依赖安装说明检查

- [ ] `requirements.txt` 存在且内容与当前代码引用一致。
- [ ] README 中安装命令与 `requirements.txt` 匹配。
- [ ] 在干净虚拟环境中执行 `pip install -r requirements.txt`，确认可以安装成功。
- [ ] 确认没有未声明但运行必需的第三方依赖。
- [ ] 确认本次发布没有额外的系统级依赖被遗漏说明。

## 5. 测试可运行性检查

- [ ] 先运行最小 smoke / prompt / CLI 相关测试，确认基础能力是否可执行。
- [ ] 再运行 `pytest -q`，确认整体测试状态。
- [ ] 若存在失败测试，记录失败原因、影响范围、是否阻塞本次发布。
- [ ] 若测试依赖外部模型服务，确认哪些测试是纯本地、哪些测试需要联网或密钥。
- [ ] 对外发布前至少保留一组可以在本地稳定通过的最小回归测试。

## 6. prompts 文件齐全性检查

- [ ] `prompts/` 目录存在。
- [ ] 当前主流程所需 prompt 文件存在且命名与代码引用一致。
- [ ] 非主流程但已有服务依赖的 prompt 文件也存在。
- [ ] prompt 文件编码正常，文本可读，无空文件、误删或损坏。
- [ ] 发布前不要随意改动 `prompts/` 文本，除非有明确需求或覆盖测试。

## 7. data 目录合理性检查

- [ ] `data/` 目录存在，且首次运行时不会因为目录缺失直接失败。
- [ ] `data/chapters/` 等预期子目录存在或可自动创建。
- [ ] 仓库中未误提交真实业务数据、隐私内容或大体积生成产物。
- [ ] README 说明了 `data/` 用于本地落盘，而不是稳定数据库或远程存储。
- [ ] 手动确认默认输出文件路径是否符合 MVP 预期，例如 `data/book.json`。
- [ ] 明确发布后是否需要清理旧生成文件，避免演示数据污染。

## 8. 硬编码路径与可移植性检查

- [ ] 搜索代码与文档中的绝对路径、机器相关路径、用户目录路径。
- [ ] 确认默认输出路径没有写死到某一台机器的绝对目录。
- [ ] 确认路径分隔符写法在当前目标平台可运行。
- [ ] 若存在硬编码路径，确认是否需要在 README 中显式说明限制。

## 9. 未完成占位逻辑检查

- [ ] 搜索 `TODO`、`FIXME`、`NotImplemented`、`placeholder` 等明显未完成标记。
- [ ] 区分目录保留用 `.gitkeep` 注释与真正的业务占位逻辑。
- [ ] 检查是否存在“模块已经存在，但主流程未接入”的情况，并在 README/发布说明中明确写出。
- [ ] 检查是否存在仅为测试通过而保留、但实际行为不完整的临时逻辑。
- [ ] 若发现未完成能力，确认本次发布是隐藏、说明限制，还是直接阻塞发布。

## 10. 人工冒烟检查

- [ ] 按 README 步骤从零安装一次，确认新环境能跑起来。
- [ ] 配置最小 `.env` 后执行 `python app.py`，确认交互流程可走通。
- [ ] 至少完成一次最小输入演示，确认输出可读且能落盘。
- [ ] 人工查看输出的 JSON / 文本结构，确认字段基本完整。
- [ ] 断开或故意写错配置后，再跑一次，确认失败提示可理解。

## 11. 当前仓库已观察到的发布风险

- [ ] 当前最小相关测试并非全部通过。
  说明：已执行 `pytest -q tests/test_project_smoke.py tests/test_prompt_loader.py tests/test_app.py`，其中 `tests/test_app.py` 有 3 个失败。
- [ ] 确认 `tests/test_app.py` 是否仍应适配当前 CLI 实现。
  说明：这些测试仍在 monkeypatch `app.generate_outline` / `app.save_json`，而当前 `app.py` 已改为走 `core.workflow_service`。
- [ ] 确认 README 编码与终端显示是否正常。
  说明：本地读取时 README 存在中文乱码现象，发布前应人工复查文件编码与展示效果。
- [ ] 确认默认输出路径 `data/book.json` 是否接受继续保持硬编码。
  说明：当前 `app.py` 中存在固定 `SAVE_PATH = "data/book.json"`。
- [ ] 确认当前 `prompts/` 文件集合满足现有服务需要。
  说明：已看到 `outline.txt`、`chapter_plan.txt`、`draft.txt`、`consistency_check.txt`、`rewrite.txt`。
- [ ] 确认当前 `data/` 目录仍是最小占位结构。
  说明：当前仅见 `.gitkeep` 与 `data/chapters/.gitkeep`，发布前应确认是否符合演示预期。
- [ ] 确认示例占位文本不会被误认为可直接上线配置。
  说明：README 中存在 `OPENAI_API_KEY=your_api_key` 示例值，这是正常示例，但发布时要避免用户误解为默认可运行。

## 12. 发布决策

- [ ] 以上阻塞项全部确认完成后，再决定是否发布。
- [ ] 若测试未修复、README 编码未确认、主流程边界未说明清楚，则本次只适合内部试用，不建议对外宣称稳定发布。
